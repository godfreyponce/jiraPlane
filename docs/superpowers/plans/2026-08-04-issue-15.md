**Goal:** Releasing a dragged plane re-seeds flight progress from the drop point (drop early
= rewind, drop late = jump ahead); a flight tolerates three grabs, then the plane stops
being grabbable and bolts to the exit clearly faster than cruise.

**Architecture:** #11 made motion a pure function of flight-time `s`; a release currently
resumes `s` where the grab froze it. This ticket changes the release to *re-seed the
clock*: invert `courseX` at the drop x to get `s₂`, set `pausedMs` so `flightS()` returns
`s₂` right now (negative `pausedMs` is fine — it just means the clock jumped ahead). The
x-offset becomes zero by construction, so #11's spring machinery survives unchanged to
handle y (per the release-path pick) and the residual x when `s₂` clamps at the course
ends. Swoop and attitude are functions of `s` and would pop at the jump: the swoop delta
is folded into `off.y` at release (always — continuity, not a feel option), the attitude
delta decays exponentially. The fast exit is a second clock branch — `s` advances at
`EXIT_RATE ×` real time from a wall-clock anchor — so it stays a deterministic function of
the shared clock and multi-display windows need no per-frame IPC once the recovery hands
off. Teardown: the renderer now tells main the projected end wall-time directly
(`endAtMs`), instead of main re-deriving it from `pausedMs`.

**Tech Stack:** Vanilla JS in `plane.html`, Electron IPC through the existing sandboxed
`preload.js`. No new dependencies.

## The re-seed, precisely

At release (all grabs), with `sHeld` = the frozen grab-time `s`:

```js
const dropX = courseX(sHeld) + off.x;               // plane's global x right now
let s2 = (dropX - fromX) / (toX - fromX) * durS;    // invert courseX
s2 = Math.max(0, Math.min(durS, s2));               // clamp at the course ends
pausedMs = Date.now() - startAt - s2 * 1000;        // re-seed: flightS() === s2 now
heldSince = null;
off.x = dropX - courseX(s2);                        // 0 unless s2 clamped
off.y += swoopY(sHeld) - swoopY(s2);                // fold the swoop jump — no vertical pop
attDelta = { z: ..., x: ..., y: ... };              // attitude(sHeld) − attitude(s2), decays
```

Why the existing plumbing survives:

- `flightS()` already computes `(now - startAt - pausedMs)/1000` — a re-seeded (possibly
  negative) `pausedMs` needs no change there.
- Main's teardown formula `flightStartAt + flightDurMs + pausedMs + 1000 - Date.now()`
  is *already correct* under re-seeding: it reduces to `releaseTime + (durS − s2)·1000
  + 1000` — rewinds extend it, forward drops shorten it. Task 2 therefore touches only
  `plane.html`; the `endAtMs` payload switch waits for Task 3, where the exit breaks
  that formula.
- The multi-display handoff already broadcasts `pausedMs` and `off` in the final
  `'course'` message — siblings adopt the re-seeded clock with zero new IPC in Task 2.

## Risks / known edges (accepted for v1 unless gate 2 says otherwise)

- **Audio:** the whoosh envelope is fixed at launch; scrubs desync it and a rewind can
  outlive it entirely (owner decision 3). Accepted rough edge, no code.
- **Drop clamped at a course end:** `s2` clamps and the residual lands in `off.x` for the
  spring — no teleport, but a drop far past the exit means a near-immediate flight end;
  the +1000ms teardown slack absorbs the recovery in the typical case (same accepted edge
  as #11's "drop near the flight's end").
- **Skywriter re-fly:** N/A — skywriter is not draggable, so nothing ever re-flies over
  laid-down smoke.
- **Sub-degree pose gap at handoff:** siblings adopt the clock while the owner may hold a
  residual `attDelta` < 0.5° — invisible by construction of the rejoin epsilon.
- **Exit determinism:** multi-display exit sync relies on the exit visuals being pure
  functions of the wall clock (`exitK` from `exitAt.t`, not per-frame state). The code in
  Task 1 Step 3 is written that way; keep it that way in the port.
