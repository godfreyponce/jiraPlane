**Goal:** Mid-flight, grab the plane with the cursor and drag it out of the way; on release
it recovers and completes its crossing — while tag clicks (#9), click-through, and
multi-display sync (#6) keep working.

**Architecture:** The flight's x/swoop/bank motion moves from CSS keyframes to a per-frame
JS simulation (the owner's standing "simulate, don't keyframe" rule) — a pure function of
shared wall-clock flight-time `s`, so undragged flights stay pixel-identical and
multi-display windows stay in sync with zero IPC. Drag introduces deviation state: the
window that owns the drag freezes `s` (pause-while-held, owner decision), tracks the
cursor, and on release springs a decaying offset back to the course. During
drag + recovery the owning window broadcasts rig state per frame via main to the other
displays' windows; at rejoin everyone returns to clock-driven mode with the accumulated
pause shifting the schedule. Main's fixed teardown timer becomes cancel-on-grab /
re-arm-on-release.

**Tech Stack:** Vanilla JS in `plane.html`, Electron IPC through the existing sandboxed
`preload.js`. No new dependencies.

## Why the whole flight becomes a sim (not a drag bolted onto keyframes)

The CSS `move`/`swoop`/`bank` keyframes are a *fixed schedule*; #6's multi-display sync and
main's teardown timer both lean on that schedule being constant. A plane that deviates and
recovers has no place in it — pausing/offsetting CSS animations per window would desync the
slices at the seam. A per-frame function of shared wall-clock time keeps the undragged
behavior and the sync guarantee (same machine, same clock, every window computes the same
`s` every frame), and gives drag a place to live: deviation is just an offset added on top,
owned by one window and broadcast while it's nonzero. This is the same rework that deferred
"hover slows the plane" in #9 — #11 is where it gets paid for.

## Gesture map (disambiguation with #9)

- Cursor inside **tag** hitbox → #9 behavior exactly: hot lift, click opens ticket.
- Cursor inside **plane** (`.model`) hitbox → drag territory: mousedown starts a grab,
  mousemove drags, mouseup releases. A mouseup that lands on the tag after a drag must
  **not** open the ticket (guard in Task 3).
- Where the two hitboxes overlap (tag swings near the plane): **tag wins** — it's the
  smaller, more deliberate target.
- Window arming (`setIgnoreMouseEvents(false)`) now follows `tagHot || planeHot || dragging`
  through the existing `'tag-hot'` IPC channel. While dragging, the window stays armed even
  if the cursor leaves every hitbox — macOS delivers the whole drag to the mousedown window
  (mouse capture), including coordinates beyond its bounds; that's what makes cross-display
  drag work without any handoff.

```js
// ===== flight sim (#11): motion is a pure function of flight-time s =====
const durS = params.has('dur') ? +params.get('dur') / 1000 : 10;
const multi = params.has('minX');
const ox = () => (multi ? window.screenX : 0);   // global → local, per frame
const oy = () => (multi ? window.screenY : 0);
// course endpoints in global px — same numbers the old --sx/--ex computed
const fromX = (multi ? +params.get('minX') : 0) - 1.1 * moveEl.offsetWidth;
const toX   = (multi ? +params.get('maxX') : innerWidth) + 400;
const lineY = multi ? +params.get('flyY') : innerHeight * 0.32;

function courseX(s) { return fromX + (s / durS) * (toX - fromX); }
function swoopY(s)  { return 44 * Math.cos(2 * Math.PI * s / (durS / 2)); }
function attitude(s) {
  const w = Math.sin(2 * Math.PI * s / (durS / 2));
  return { z: -14 * w, x: 5 + 16 * w, y: -10 * w };
}

// flight clock: freezes while held (#11 owner decision), pause shifts the schedule
let pausedMs = 0, heldSince = null;
function flightS() {
  const t = heldSince ?? Date.now();
  return Math.min(durS, Math.max(0, (t - startAt - pausedMs) / 1000));
}

// deviation from course: (0,0) in clean flight; cursor-driven while held;
// spring-recovered after release. Persists as a static y shift if the owner
// picks keep-drop-height.
let mode = 'course';                       // 'course' | 'drag' | 'recover'
let off = { x: 0, y: 0 }, offV = { x: 0, y: 0 };
let target = { x: 0, y: 0 };               // recovery target for off

function renderRig(gx, gyLine, sy, att) {  // global rig origin + swoop + attitude
  moveEl.style.top = gyLine - oy() + 'px';
  moveEl.style.transform = `translateX(${gx - ox()}px)`;
  swoopEl.style.transform = `translateY(${sy}px)`;
  bankEl.style.transform =
    `rotateZ(${att.z}deg) rotateX(${att.x}deg) rotateY(${att.y}deg)`;
}
```

(`swoopEl`/`bankEl` are `document.querySelector('.swoop')`/`('.bank')`, next to the
existing `moveEl`.) Per frame, the motion step:

```js
function stepFlight(dt) {
  const s = flightS();
  if (mode === 'drag') {
    off.x = (cursorG().x + grabOff.x) - courseX(s);
    off.y = (cursorG().y + grabOff.y) - lineY;
  } else if (mode === 'recover') {
    offV.x += (-K * (off.x - target.x) - D * offV.x) * dt;
    offV.y += (-K * (off.y - target.y) - D * offV.y) * dt;
    off.x += offV.x * dt; off.y += offV.y * dt;
    // REJOIN_EPS = 1 (px, px/s): snap threshold, a guess — invisible at that scale
    if (Math.hypot(off.x - target.x, off.y - target.y) < 1 &&
        Math.hypot(offV.x, offV.y) < 1) {
      off = { ...target }; offV = { x: 0, y: 0 }; mode = 'course';
    }
  }
  renderRig(courseX(s) + off.x, lineY + off.y, swoopY(s), attitude(s));
}
```

`cursorG()` maps the last mousemove to global px (`clientX + ox()`); `grabOff` is set at
mousedown so the plane doesn't jump to the cursor. Note what falls out for free: `s` is
frozen while held, so swoop and bank freeze at the grab pose without extra code.

```js
let grabOff = { x: 0, y: 0 }, flingV = { x: 0, y: 0 }, prevCursor = null;

addEventListener('mousedown', (e) => {
```

## Risks / known edges (accepted for v1 unless gate 2 says otherwise)

- **Drop near the flight's end, far from the exit:** the teardown re-arms at release from
  the *schedule*, not the recovery; a plane flung far left seconds before `s` hits `durS`
  could still be recovering when teardown fires (+1000ms slack absorbs the typical case).
  If it pops visibly at gate 2, the fix is a renderer-sent "rejoined" re-arm — don't build
  it preemptively.
- **Audio envelope:** the whoosh is scheduled against the original duration at launch; a
  long hold means the sound ends before the (shifted) flight does. Audio is optional by
  design; accepted rough edge.
- **`attitude` freeze at grab:** if the owner skipped ease-to-level, a plane grabbed
  mid-bank hangs frozen at that pose — that's the picked behavior, judged in the prototype.
- **Sim parity:** Task 2 rides on the formulas matching the keyframe tables (they were
  derived from them: swoop `44·cos(2πs/(dur/2))`, bank `sin` scaled by −14/16/−10 around
  the 5° base). Verify step 1 of Task 2 is the eyeball proof; any mismatch means a formula
  transcription bug, not a design problem.
