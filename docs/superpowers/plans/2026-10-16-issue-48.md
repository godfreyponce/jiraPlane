# Update check in the popover — Implementation Plan (jiraPlane #48)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement
> this plan. Steps use checkbox (`- [ ]`) syntax for tracking. **Multi-task plan:** build on
> the ticket branch `issue-48` (the worktree is already on it), one commit per task, in the
> AGENTS.md `# Commit format`: `summary (refs #48)`, no type prefix, never `fixes`, trailer =
> the harness `Co-Authored-By` line only. **Two stops:** Task 3 Step 3 is the owner's variant
> pick; Task 5 Step 2 is gate 2. Stop at each. Never merge to main yourself.

**Goal:** When the owner pushes a new `vX.Y.Z` tag, the popover shows one line and an Update
button; the click checks out the tag, runs `npm install`, and restarts the running instance once
no plane is in the air. Nothing happens without the click.

**Architecture:** A new `updater.js` owns the git/npm process work (resolve binaries, fetch tags,
pick the newest `vX.Y.Z` not already in HEAD, refuse on local edits or a foreign branch,
checkout + install). `main.js` owns the schedule (launch + daily), the `update` field of the
popover state, the flight hold, and the restart (launchd job: exit non-zero so KeepAlive brings
it back as `com.jiraplane.app`; dev run: `app.relaunch()`). `popover.html` renders the `update`
field as the owner's picked variant, rebuilding that block only when its content changes so the
1 s push (#39) never swallows a click.

**Tech Stack:** Electron ^43.2.0, vanilla HTML/CSS/JS, `child_process.execFile`. No new
dependency.

**Spec:** No design spec. The decision record is issue #48's body
(`gh issue view 48 --json body -q .body`; no comments; blockers #41 and #45 are closed) and
the owner decisions it lists (Q1–Q6). Related: `docs/HISTORY.md` #24 (launchd PATH), #29
(the `launchctl print` login-job test), #45 (manual update path), #39 (1 s popover push).

## Global Constraints

Copied from #48 and AGENTS.md. Every step inherits these.

- Notify plus one click only. No silent update, no restart without the click.
- Only `vX.Y.Z` tags count. New commits on main never do.
- The UI is one line plus a button in `popover.html`. No tray-menu item, no Settings entry.
- Local edits are never stashed, reset, or touched. The updater refuses and says why.
- `npm install` failure: the running app keeps running, the popover shows the error and
  points at the manual steps. No automatic rollback.
- No tags, no remote, no network: no update line, one log line, nothing else.
- Absolute paths for `git` and `npm` (launchd's default PATH is `/usr/bin:/bin:/usr/sbin:/sbin`,
  #24). `npm` is a `#!/usr/bin/env node` script (`/usr/local/bin/npm` on the owner's Mac), so
  its own directory is prepended to `PATH` for the child, or `env` cannot find `node`.
- The popover re-renders every second while open (#39). The update block must keep its DOM
  nodes across pushes whose `update` content is unchanged.
- Push over IPC from main. No timers in `popover.html`. No `innerHTML`.
- Visuals: three single-file HTML variants first (AGENTS.md `# Visual rule`), three shapes,
  in `design-directions/` (ignored via `.git/info/exclude`, shared with the main checkout).
  The owner picks; the winner is wired into `popover.html`; losers stay in the folder.
- One running app instance at a time. Subagents never launch the app. Quit every `npm start`
  you launch. The always-on login instance (`com.jiraplane.app`, program under
  `~/Developer/jiraPlane`) holds the single-instance lock: ask the owner to tray-Quit it before
  any live run. Never bootout, kickstart, or reinstall the login job yourself (#45: the
  classifier blocks it; the owner does that part).
- This session's shell sets `ELECTRON_RUN_AS_NODE=1`, which crashes `main.js:11`. Prefix every
  launch with `env -u ELECTRON_RUN_AS_NODE TEAMS_WEBHOOK_URL=` so no run sends a Teams DM.
  Run the app as a background task and stop it with TaskStop.
- The worktree has no `node_modules`. Run `npm install` in it once before any live run.
- Written as if public: no env values, credentials, real issue keys, or personal data in
  commits, variants, the plan, or the gate 2 report. Never copy `.env` anywhere.

## Decisions the owner may want to overturn

Most likely to be wrong first.

1. **"Newer" means "not already in HEAD", decided by ancestry, and #45's manual path moves
   from `git pull` to "check out the newest tag".** The newest `vX.Y.Z` tag (semver order) is
   offered iff `git merge-base --is-ancestor <tag> HEAD` fails. A coworker on main ahead of the
   tag is never offered a downgrade; a clone at an older tag or an older main is. After one
   update the clone sits detached at the tag, so `git pull` would stop working; ONBOARDING § 7
   becomes `git fetch --tags` + `git checkout <newest tag>`. This settles the ticket's first
   fog item with both halves.
2. **Where the clone may be:** on `main` (pre-updater coworkers) or detached (post-updater).
   Any other branch is refused ("on branch X"), so the owner's worktrees never update
   themselves. Local edits = any modified tracked file (`git status --porcelain
   --untracked-files=no` non-empty); untracked files are not edits (`.env`, `state.json`,
   `settings.json` are ignored anyway).
3. **The login instance restarts by exiting non-zero.** `app.exit(1)` from the launchd job
   makes KeepAlive (`SuccessfulExit=false`) start it again as `com.jiraplane.app` from the
   plist's program path, which is unchanged by the update. A dev `npm start` restarts with
   `app.relaunch(); app.exit(0)`; the new instance is detached from the terminal (same
   working directory and arguments). The login-job test is #29's: `launchctl print` lists this
   pid. The owner proves the launchd case at gate 2; the agent proves the dev case on a
   scratch clone (Task 5).
4. **Flights are held from the click until the restart.** While `update.phase` is
   `installing` or `restarting`, `flyNext` starts nothing: a flight that began after the
   checkout would load the new `plane.html` under the old `main.js`. The active flight finishes;
   the restart fires when its windows close. Queued flights are discarded at restart (#31's
   rule for quit; state has already advanced). If the install fails, the hold lifts and the
   queue drains.
5. **`UPDATE_NOW=1` runs the click path at launch** (an env hook like `TEST_FLIGHT`,
   `OPEN_POPOVER`, `OPEN_SETTINGS`), so the agent can prove the whole chain without clicking
   the panel. After a restart the clone is at the tag, the check finds nothing, and the hook
   does nothing: no loop.
6. **The first tag is cut at accept time: `v0.1.0`**, matching `package.json`'s version, on the
   merge commit that carries the updater. Later tags are the owner's ad hoc call (second fog
   item); the plan adds no AGENTS.md rule. Suggestion, not built: bump `package.json`'s
   `version` in the docs commit of any accept you tag, so Settings → About matches the tag.
7. **The update check runs at launch and every 24 h** (`UPDATE_CHECK_MS`, the ticket's own
   guess). `git fetch` gets a 60 s `timeout` (a guess, labelled so) so a hung fetch cannot
   wedge the one-at-a-time guard for the day.
8. **A failed install leaves HEAD at the new tag** with the old `node_modules`. The running
   process is unaffected; the popover shows "Update failed: <last stderr line>" and names
   ONBOARDING § 7, whose `npm install` + restart finishes the job. Rolling back the checkout
   would be the "automatic rollback" the ticket rules out.
9. **Clicking Update closes the panel first**, like every other popover action. Reopening it
   shows the phase ("Updating to v0.2.0…", "Restarting after this flight…", or the error).
10. **No `ready-for-agent` label.** The owner typing `/run-ticket 48` was the confirmation.

### Task 2: `updater.js`

**Files:**
- Create: `updater.js`

**Interfaces:**
- Produces, for Task 3:

```js
// updater.js — git/npm process work for #48. No Electron import: runnable under plain node.
module.exports = {
  GIT_BIN,   // string: first existing of process.env.PATH entries, '/opt/homebrew/bin', '/usr/local/bin', '/usr/bin' that holds `git`; '' if none
  NPM_BIN,   // same search for `npm`; '' if none
  check(repoDir),        // Promise<string|null>: newest vX.Y.Z tag not an ancestor of HEAD, or null (none / up to date). Rejects when `git fetch` fails.
  blocker(repoDir),      // Promise<string>: '' when the clone may update, else the reason
  install(repoDir, tag), // Promise<void>: checkout the tag, then npm install. Rejects with Error(last non-empty stderr line)
};
```

- [ ] **Step 1: Write `updater.js`**

`run(bin, args, repoDir)` wraps `execFile` with `{ cwd: repoDir, env, timeout: 60_000, maxBuffer: 8 * 1024 * 1024 }`
and resolves `{ stdout, stderr }`, rejecting with `Error` whose message is the last non-empty
line of stderr (or the exec error message). `env` = `process.env` with
`PATH = path.dirname(NPM_BIN) + ':' + process.env.PATH` (the shebang constraint). The npm
install call uses no timeout (an Electron download can take minutes); the 60 s is for git.

Resolution: `resolveBin(name)` searches, in order, `process.env.PATH.split(':')`, then
`/opt/homebrew/bin`, `/usr/local/bin`, `/usr/bin`, returning the first `path.join(dir, name)`
that `fs.existsSync`; `''` if none. Evaluated once at module load.

`check(repoDir)`:
1. `GIT_BIN` empty → reject `Error('git not found')`.
2. `git fetch --quiet --tags origin`.
3. `git tag -l 'v*' --sort=-v:refname` → first line matching `/^v\d+\.\d+\.\d+$/`; none → `null`.
4. `git merge-base --is-ancestor <tag> HEAD` → exit 0 → `null`; exit 1 → the tag; other → reject.

`blocker(repoDir)` returns the first that applies, else `''`:
- `GIT_BIN` empty → `git not found`; `NPM_BIN` empty → `npm not found on this PATH`
- `git status --porcelain --untracked-files=no` non-empty → `local edits in <first 3 filenames, comma-separated>`
- `git symbolic-ref --short -q HEAD` exits 0 with a name other than `main` → `on branch <name>`

`install(repoDir, tag)`: `git -c advice.detachedHead=false checkout --detach <tag>`, then
`npm install`. Log each command's start and end with `console.log` in the `#22` form
(`<iso> update: <command> ok|failed`).
