# Popover status header — Implementation Plan (jiraPlane #39)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement
> this plan. Steps use checkbox (`- [ ]`) syntax for tracking. **Single-task plan:** the code
> stays uncommitted in the working tree until the owner accepts (AGENTS.md "One ticket = two
> sessions"). No ticket branch. **Task 2 Step 2 is gate 2.** Stop there.

**Goal:** The popover header shows real poll state, live: the last-poll time, "Paused", or why
polling is off. Its Pause switch drives the same `pollingPaused` flag as the native menu item
and the #29 settings window.

**Architecture:** Main owns all state and all timing. It sends the #37 state object to the
popover on `'popover-state'`: on page load, after every successful poll, on every pause change
(through `refreshSurfaces`), just before every show, and once a second while the panel is
open. The page renders what it gets, sends the Pause intent back, and reports its panel
height after each render so main can size the window to fit.

**Tech Stack:** Electron 43.2.0, vanilla HTML/CSS/JS. No new dependency.

**Spec:** No design spec. The decision record is:
- issue #39's body (`gh issue view 39 --json body -q .body`; the plain `--comments` form
  prints only comments). It has no comments.
- issue #36's body (owner decisions, 2026-09-24): Q4 put Pause in both the popover and the
  settings window, with one state.
- the #37 state and bridge contract (`docs/superpowers/plans/2026-10-12-issue-37.md`, "The
  contract"). `popover.html` already renders it.
- `docs/HISTORY.md`, the #38 and #37 sections (lines 14–72).

## Decisions the owner may want to overturn

Most likely to be wrong first.

1. **Main re-sends the state once a second while the panel is open.** The ticket names pushes
   on every tick and every pause change. Without this clock, the header reads "Last poll just
   now" for up to 59 s while the panel stays open. Then the two-tick update in Done-when 1
   cannot be seen, because the header reads "just now" before and after each tick. The 1 s
   value is the finest unit the page's `ago()` prints. The timer lives in main, so the
   "renderer never times anything" constraint holds. **What this costs #40:** each push re-runs
   `render()`, which rebuilds the list rows. A row click that spans a rebuild is lost, so #40
   must rebuild rows only when the list changes. If you strike this decision, delete `popoverClock` and its
   `'show'`/`'hide'` lines in Step 3, and the header shows no change between ticks.
2. **The window resizes to fit the panel, which pulls part of #40 into #39.** The page sends
   its panel height after each render and main calls `setSize`. Reason: with a config error,
   the status line reads "Polling disabled: missing JIRA_PAT (set it in .env)". #37 measured
   212 px for a status of that length (two lines), and the window is fixed at 197 px. At 197
   px the Quit row is cut off. #40's rows need the same resize, so #40 gets it built.
3. **"Last poll" counts successful polls only.** When a poll fails (Jira unreachable, VPN
   off), the old time keeps aging ("Last poll 4m ago"). Before the first success, the header
   keeps "Waiting for first poll". The alternative stamps every finished poll, but then the
   header says "just now" while every poll fails.
4. **Wording comes from the #37 pick, not the ticket.** The header reads "Last poll 12s ago"
   (no colon), not the ticket's "Last poll: …". While paused it reads "Paused" in orange, with
   no time. Both are already in `popover.html`. The owner picked them after writing #39.
5. **The panel stays open when the Pause switch is clicked.** It is a switch, not a menu row,
   and the header shows the result. The three footer rows still close the panel (#38).
6. **No new design variants.** AGENTS.md's visual rule asks for three variants first. #37 ran
   that round for the whole panel, header included, and the owner picked popover-1-menu on
   2026-10-13. This ticket puts data into that pick and changes no CSS or markup.
7. **No `ready-for-agent` label.** The owner typing `/plan-ticket 39` was the confirmation.

## Review Focus

The inputs most likely to break the header that a happy-path launch does not exercise. Each
line names the check that pins it.

1. **A config error wraps the status to two lines.** The window must grow so the Quit row is
   whole, and the Pause switch is disabled. Pinned: Task 1 Step 7 (run 2): probe height and
   screenshot.
2. **Jira is unreachable.** The header must not claim a fresh poll. It keeps "Waiting for
   first poll" (or an aging time). Pinned: Task 1 Step 8 (run 3).
3. **Pause changed from a different surface while the panel is closed.** The native menu, the
   settings window, and the panel must agree the next time each is looked at. After resume,
   the header shows the old time until the next poll, not "just now". Pinned: gate 2 items 3
   and 4.
4. **The panel stays open across polls.** The time counts up each second and drops back after
   each poll. A footer row's hover highlight survives the 1 s re-render (footer rows are not
   rebuilt). Pinned: Task 1 Step 6 (run 1) crops, gate 2 items 1 and 2.
5. **The panel opens after a long hidden spell.** The first frame shows the current time.
   It must not show the value from before the panel was hidden and then jump. Pinned: the push
   before `show()` (Step 3), gate 2 item 5. The agent cannot click the tray, so this is the
   owner's.
