# Popover version line without branch or dots — Implementation Plan (jiraPlane #58)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement
> this plan. Steps use checkbox (`- [ ]`) syntax for tracking. **Single-task plan:** the code
> stays uncommitted in the working tree of this worktree (branch `issue-58`). Never commit,
> never merge to main. Two stops: Step 3 (the owner picks a variant) and Step 9 (gate 2).

**Goal:** The popover's update line shows the version on the left and `checked 42s ago` on the
right, muted, with no branch name and no ` · `. A checkout past the newest tag shows the plain
tag. The release command is written down, and `npm version` makes a `release vX.Y.Z` commit.

**Architecture:** Only the popover's rendering of the `update` field changes. `current` and
`ahead` render the same line: the tag left, the checked time right. The other #57/#48 phases
keep their words and lose their ` · `. The `ref` field leaves the popover contract, because the
popover no longer reads it. `updater.check()` still returns `ref` for the `main.js` log line.
A new one-line `.npmrc` sets the `npm version` commit message. The release command goes into
STATE.md in the accept-time docs commit.

**Tech Stack:** Electron ^43.2.0, vanilla HTML/CSS/JS. No new dependency.

**Spec:** No design spec. The decision record is issue #58's body
(`gh issue view 58 --json body -q .body`, no comments). It builds on #57
(`docs/superpowers/plans/2026-10-19-issue-57.md`: the `update` contract and its phases) and
#48 (the `update-2-head` header slot).

## Global Constraints

From #58 and AGENTS.md. Every step inherits these.

- Visual rule (AGENTS.md `# Visual rule`): "Anything visual gets 3 single-file HTML variants
  first; the owner picks; the winner gets wired in. Three variants means three shapes — a second
  flavor of the first shape doesn't count. Variants go in `design-directions/` (git-ignored; the
  #3/#4 precedent); the winner is wired into `plane.html`, and the losing variants are kept
  there." For this ticket the winner goes into `popover.html` (the ticket says so).
- About keeps reading `app.getVersion()`. `settings.html` and its `version` field do not change.
- No CI release workflow.
- `updater.js` does not change.
- No branch name and no ` · ` in any update line the popover shows.
- The 1 s push rule from #57 holds: `#update` is rebuilt only when its key changes, and between
  changes only the text moves, so the Update button stays the same DOM node.
- Panel width stays 320 px. Text that overflows ellipsizes or clamps; it never scrolls sideways.

## Decisions the owner may want to overturn

Most likely to be wrong first.

1. **`Up to date` goes away.** On the tag and past the tag, the line is only `v0.1.5` on the
   left and `checked 42s ago` on the right. The ticket's layout sentence names only those two
   parts, and its list of "other states" leaves `Up to date` out. If the owner wants the words
   back, they go after the tag on the left (`v0.1.5 Up to date`), for `current` only.
2. **The release command is written in STATE.md `## Run / verify`, not README.md.** README.md
   talks to coworkers in the owner's voice; cutting a release is the owner's job, and every
   agent session starts at STATE.md. It lands in the accept-time docs commit (AGENTS.md: STATE.md
   is written once, at accept).
3. **`.npmrc` is added** with `message=release v%s`, so a release commit reads `release v0.1.6`
   instead of a bare `0.1.6`. It does not carry `(refs #N)`: a release is not a ticket.
4. **`ref` leaves the popover contract.** `main.js` stops putting `ref` in the `update` object
   (3 places) because nothing reads it any more. `updater.check()` keeps returning it for the
   `update: check: main ahead of v0.1.5` log line. Keeping the field would be harmless but dead.
5. **"Same version" means the same number.** About reads `jiraPlane 0.1.5`; the popover reads
   `v0.1.5`. The ticket's own example keeps the `v`, and About must not change.
6. **`check-failed` keeps its time on the right**: `Couldn't check for updates` left, `checked 3h
   ago` right. With no good check yet, the right side is empty.

## Copy (exact, for every variant and the winner)

`ago()` is popover.html's existing function. "Left" and "right" are the two ends of one line.

| phase | left | right | tone |
|---|---|---|---|
| `checking` | `Checking for updates…` | — | muted |

| `ahead` | `${tag}` | `checked ${ago(checkedAt)}` | muted |
| `check-failed` | `Couldn't check for updates` | `checked ${ago(checkedAt)}`, or nothing when `checkedAt` is null | muted |

| `installing` | `Updating to ${tag}…` | — | muted |
| `restarting` | `Restarting after this flight…` | — | muted |

| `failed` | `Update failed: ${detail}. See ONBOARDING § 7.` (full width, 2-line clamp) | — | error |

ticking time does not shift.
