# Popover recent flights — Implementation Plan (jiraPlane #40)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement
> this plan. Steps use checkbox (`- [ ]`) syntax for tracking. **Single-task plan:** the code
> stays uncommitted in the working tree until the owner accepts (AGENTS.md "One ticket = two
> sessions"). No ticket branch. **Task 2 Step 2 is gate 2.** Stop there.

**Goal:** The popover's "Recent flights" section lists the last 5 real flights, newest first,
and a click on a row re-flies that flight through #34's replay path (plane only, no Teams DM).

**Architecture:** Main's single remembered event (`lastFlown`, #34) becomes a ring of at most
5 (`recentFlights`, newest first). The native Replay item reads `recentFlights[0]`; the
popover state's `flights` field is the ring, mapped to the #37 contract shape. The page
already renders rows from `state.flights` and calls `api.replay(i)`; this ticket adds the
`replay` bridge call, the `'popover-replay'` handler, and makes the rows survive the 1 s
state push (#39) by rebuilding them only when the list changes.

**Tech Stack:** Electron 43.2.0, vanilla HTML/CSS/JS. No new dependency.

**Spec:** No design spec. The decision record is:
- issue #40's body (`gh issue view 40 --json body -q .body`). It has no comments. Its
  blockers #38 and #34 are both closed.
- issue #36's body (owner decisions, 2026-09-24): rows are key + snippet + relative time,
  click to replay, in-memory, same exclusions as #34 (no test flights, no digest, no
  reassigned).
- the #37 state and bridge contract (`docs/superpowers/plans/2026-10-12-issue-37.md`, "The
  contract"): `flights: [{ issueKey, snippet, at }]`, newest first, ≤ 5; the page calls
  `api.replay(index)`.
- `docs/HISTORY.md`, the #34 section (line 187) for the replay rules, and the #39 section
  (line 14) for the push schedule.

## Global Constraints

Copied from #40, #36 and AGENTS.md. Every step inherits these.

- One remembered-flights structure in main, shared by the #34 menu item and the list. `lastFlown`
  is deleted, not kept beside the ring. After the build, `grep -c lastFlown main.js` is `0`.
- Replay never goes through `dispatchEvent`: `enqueueFlight` only, so the Teams sink never
  sees a replay (#34).
- The ring takes only `assigned` / `mention` / `comment` events without `test: true` (#34's

- Push over IPC from main. The renderer never polls or times anything: no `setInterval`,
  `setTimeout`, or `requestAnimationFrame` in `popover.html`. No `innerHTML`.
- No new dependency. One new log line at most (none planned).
- One running app instance at a time. Subagents never launch the app. Quit every `npm start`

## Decisions the owner may want to overturn

Most likely to be wrong first.

1. **A row's time is when the app detected the event, not Jira's timestamp.** Poller events
   carry `{ type, issueKey, snippet }` and nothing else (`poller.js:236`); the Jira comment or
   assignment time never reaches main. The ring stamps `at: Date.now()` in `dispatchEvent`,
   which is the poll that found it, up to 60 s after the Jira action. Reading Jira's time
   would mean a poller change outside this ticket. If you want Jira's time, say so and this
   becomes a two-file change with a `poller.js` task.
2. **Rows are addressed by index, as the #37 contract says, with a ≤ 1 s stale window.** A
   click sends the row's index; main replays `recentFlights[index]`. If a real event lands
   between the last push and the click, the ring has shifted and the click replays the
   flight one above the one the owner saw. The panel re-renders within 1 s of any poll
   (#39's clock), so the window is at most 1 s, once a minute at most. The alternative is a
   per-flight id; it is more code for a race the owner will rarely see. Strike this and the
   plan adds `id` (a counter) to each ring entry and sends it instead of the index.
3. **Rows rebuild only when the list changes; otherwise only the time text updates.** STATE.md's
   gotcha from #39: each 1 s push re-runs `render()`, and a click whose mousedown lands on a
   row that is replaced before mouseup is lost. The page keeps a signature of the rendered
   list (`at` and `issueKey` per row) and, when it matches, writes the new times into the
   existing `.time` spans. A list change (new flight, or the first flight) rebuilds the rows.
4. **No new design variants.** AGENTS.md's visual rule asks for three variants first. #37 ran
   that round for the whole panel with the five-row list in it, and the owner picked
   popover-1-menu on 2026-10-13. `popover.html` already holds the row markup, CSS, and the
   "No flights yet" empty state. This ticket puts data into that pick and changes no CSS or
   markup.
5. **The cap is 5, as a named constant.** The ticket calls 5 a guess; `RECENT_FLIGHTS_MAX = 5`
   in `main.js` is the one place to change it. #37 measured the panel at 293 px with 5 rows.
6. **The agent cannot prove the real-event rows itself.** Only real Jira activity enters the
   ring, and the agent has no way to fake a real event without adding code. The agent proves
   the page side in a browser, the empty state and the test-flight exclusion in the live app,
   and the owner proves the real rows and the click at gate 2 (comment on your own ticket).
7. **No `ready-for-agent` label.** The owner typing `/run-ticket 40` was the confirmation.

  // Main re-sends the state every second while the panel is open (#39). Rows
  // are rebuilt only when the list changes, so a click that spans a push still
  // lands on the row it started on; between changes only the times move.
  const flightsKey = state.flights.map((f) => `${f.at}:${f.issueKey}`).join('\n');
  if (flightsKey === shownFlightsKey) {
    document.querySelectorAll('#flights .time').forEach((el, i) => {
      el.textContent = short(state.flights[i].at);
    });
  } else {
    shownFlightsKey = flightsKey;
    const rows = state.flights.map((flight, i) => {
      const row = document.createElement('div');
      row.className = 'item flight';
      row.append(span('key', flight.issueKey), span('snippet', flight.snippet), span('time', short(flight.at)));

      const empty = document.createElement('div');
      empty.className = 'empty';
      empty.textContent = 'No flights yet';
      rows.push(empty);
    }
    $('flights').replaceChildren(...rows);
  }
