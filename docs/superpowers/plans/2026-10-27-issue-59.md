# Digest names its tickets — Implementation Plan (jiraPlane #59)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement
> this plan. Steps use checkbox (`- [ ]`) syntax for tracking. **Single-task plan:** the change
> stays uncommitted in the working tree of this worktree (branch `t3/rt-59`). Never commit,
> never merge to main. One stop: Step 8 is gate 2.

**Goal:** A flood-valve digest says which tickets it collapsed. The DM lists one line per
ticket, and both the DM link and the digest plane's cargo tag open a Jira search for exactly
those tickets.

**Architecture:** `poller.js` groups the burst's events into per-ticket items (in the order the
poller found them) and builds the `key in (...)` search URL once. Both go on the digest event as
`items` and `url`. `teams.js` renders the items into the existing `snippet` field. `main.js`
uses `event.url` as the flight's click URL when it is set. One URL, built in one place, so the
DM link and the cargo tag cannot drift apart.

**Tech Stack:** Electron ^43.2.0, Node built-ins. No new dependency.

**Spec:** No design spec. The decision record is issue #59's body (`gh issue view 59`). It has
no comments.

## Decisions the owner may want to overturn

Most likely to be wrong first.

1. **The list is one line, tickets joined with `; `. No line-break probe.** The ticket says to
   check whether the field renders line breaks. `sanitize()` turns every control character,
   newline included, into a space. That is on purpose: the flow pastes each field into a JSON
   string literal, and a raw newline there breaks the card. A newline would need a bypass of
   `sanitize()`, which the ticket forbids. And the builder cannot see Teams to judge the
   render. So the builder ships the ticket's fallback form. If the owner wants line breaks, that
   is a follow-up that changes the flow too.
2. **`snippet` carries the list, `subline` keeps the counts, and the old snippet sentence goes.**
   Today `snippet` holds "More than 3 alerts in one cycle were collapsed into this digest to
   avoid webhook throttling." The list replaces it. The headline "Update burst." and the counts
   line still say what happened. The other choice: put the list in `subline` (replacing the
   counts) and keep the sentence.
3. **The URL is built in `poller.js`, not in `teams.js`.** The ticket's "Probably touches" puts
   it in `teams.js`. Building it once on the event means `main.js` reads the same string, so
   the "same search" Done-when line holds by construction.
4. **Comment authors are listed once each.** Two comments by one person read
   `2 comments (A)`, not `2 comments (A, A)`. Mentions use the owner's wording verbatim:
   `mentioned you by A` (several people: `mentioned you by A, B`).

- Produces: the digest event gains two fields. No new export.

```js
{
  type: 'digest',
  issueKey: '',
  snippet: `${events.length} Jira updates`,   // unchanged (plane banner)
  counts: { comments, assigned, reassigned }, // unchanged
  items: [{
    issueKey: string,
    summary: string,           // the event's `snippet` (the ticket summary)
    assigned: boolean,
    commentAuthors: string[],  // one entry per comment event, duplicates kept
    mentionAuthors: string[],  // one entry per mention event, duplicates kept
    reassigned: boolean,
    newAssignee: string|null,  // only meaningful when reassigned
  }],                          // ticket order = first appearance in `events`
  url: string,                 // `${config.baseUrl}/issues/?jql=` + encodeURIComponent(`key in (K1, K2, ...)`)
}
```
