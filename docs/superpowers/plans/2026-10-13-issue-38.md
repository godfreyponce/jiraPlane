# Tray popover shell — Implementation Plan (jiraPlane #38)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement
> this plan. Steps use checkbox (`- [ ]`) syntax for tracking. **Single-task plan:** the code
> stays uncommitted in the working tree until the owner accepts (AGENTS.md "One ticket = two
> sessions"). No ticket branch. **Task 2 Step 2 is gate 2.** Stop there.

**Goal:** Left click on the tray icon opens the #37 winner as a real anchored panel with three
working footer rows. Right click keeps today's native menu.

**Architecture:** `popover.html` is a copy of `design-directions/popover-1-menu.html` with
three small edits. It loads in one `BrowserWindow` of type `panel` (a non-activating NSPanel)
with native `menu` vibrancy. The window is created hidden at launch and is never destroyed. A
new sandboxed preload, `preload-popover.js`, gives the page the #37 bridge
(`window.jiraPlanePopover`). It serves a constant empty state and sends the three row intents to
main. The tray stops using `setContextMenu`: `'click'` toggles the panel and `'right-click'` pops
up `buildMenu()`.

**Tech Stack:** Electron 43.2.0 (`node_modules/electron/package.json`), vanilla HTML/CSS/JS.
No new dependency.

**Spec:** No design spec. The decision record is:

  the state and bridge contract above it (lines 97–200).

## Global Constraints

Copied from #38 and AGENTS.md. Every task inherits these.

- All popover visuals in ONE self-contained `popover.html` (the iterate-one-file rule of
  `plane.html` and `settings.html`).
- A new preload for the popover. The renderer never touches disk. All state goes through main.
- Reuse `releaseFromTilingWM` if AeroSpace grabs the popover. Do not invent a second release
  path. Keep `setAlwaysOnTop` last at every re-stack point (STATE.md gotcha, #12).
- No status header data and no recent-flights data. Those are #39 and #40.
- No new dependency.
- The popover never steals the plane's level. Overlays use `'screen-saver'` (layer 1000). The
  popover uses `'pop-up-menu'` (layer 101, the level of a native menu).
- One running app instance at a time. Subagents never launch the app. Quit every `npm start`
  you launch. The always-on login instance holds the single-instance lock, so the owner must
  tray-Quit it before a dev run.
- This session's shell sets `ELECTRON_RUN_AS_NODE=1`, which crashes `main.js:11`. Prefix every
  launch with `env -u ELECTRON_RUN_AS_NODE`.
- Issues and commits are written as if public: no env values, credentials, or personal data.
  Do not paste the owner's other window titles from `aerospace list-windows`; filter them out.

## Decisions the owner may want to overturn

1. **`type: 'panel'` and `show()`.** A non-activating NSPanel opens on the current Space and
   over full-screen apps, as a native menu does (Electron docs, `BaseWindowOptions.type`).
   Click-outside dismissal is the window's `'blur'` event. If `show()` does not make the panel
   key, blur never fires; Native unknown U3 has the fix. That fix activates the app, so the
   front app loses focus while the panel is open.
2. **The Pause switch is inert until #39.** The preload answers `setPaused` by re-sending the
   empty state, so the switch snaps back to off. Pause polling still works from the right-click
   menu and from Settings…. The alternatives: wire it now, which takes #39's main-to-renderer
   push channel (kept separate by owner decision Q2), or hide the switch, which edits the
   picked design.
3. **The empty state lives in the preload, not in main.** #38 adds no main-to-renderer channel
   (Q2 gives that to #39). The preload's `onState` calls back at once with the constant, so a
   switch click before any push cannot throw (#37 review note).
4. **Created hidden at launch, not on the first click.** A page load takes about 350 ms
   (measured for overlays, `main.js:20-21`). A menu that opens late feels broken. The cost is
   one renderer process that stays alive.
5. **Fixed window size 320 × 197.** This is the #37 pick's measured empty state. #38 never
   shows any other state, so the window does not measure its content. #39 (a config error is
   212) and #40 (5 rows is 293) must add a height report. The #37 review notes say so already.
6. **Rows act like menu items.** Test flight and Settings… hide the panel first, then act.
   Quit quits.
7. **Settings… opens the #29 window** (correction 2). That covers #41's first Done-when bullet.
   At accept time, ask the owner whether to note this on #41.
8. **`OPEN_POPOVER=1 npm start` opens the panel on launch.** This copies #29's `OPEN_SETTINGS=1`.
   The agent cannot click the tray, so this hook is the only way it can see the panel.
9. **One log line per open** (`popover: tray=… at=… display=…`), the same habit as #22's flight
   line. It is the agent's only record of where the icon was: status-item windows do not show
   in the CoreGraphics window list (checked 2026-10-13).
10. **Dark only.** The CSS tint sits over the `menu` material. The owner runs Dark mode. In
    Light mode the material behind the tint is light, and the muted text gets faint. Not in
    scope; noted for coworkers (#8).

## Review Focus

The inputs and conditions most likely to break the panel that the happy path never exercises.
Each line names the check that pins it.

1. **A leftover `tray.setContextMenu` anywhere.** On macOS, a tray with a context menu opens
   that menu on left click too, and Electron does not emit `'click'`. `refreshSurfaces()`
   (`main.js:62`) and `dispatchEvent()` (`main.js:362`) both call it. One missed call would
   take the left click back after the first settings change or the first real flight. Pinned:
   Task 1 Step 6 greps for it; gate 2 item 4 changes a setting, then left-clicks.
2. **The second click on the icon opens the panel again instead of closing it.** This happens
   if the icon click blurs the panel before `'click'` arrives. Pinned: gate 2 item 2; fix U2.
3. **The icon sits near the right edge of the display.** The panel must not run off-screen.
   `togglePopover` clamps x to the display's work area. Pinned: Task 1 Step 7 checks that the
   panel's right edge is at or left of the display's right edge.
4. **The AeroSpace release re-asserts `'screen-saver'`** (`main.js:131`). If the popover gets
   the release (U1), it would sit above the plane unless its own level goes back on last.
   Pinned: Task 1 Step 7 samples the layer 2 s after the open, after the release retries
   (5 × 300 ms at most) have settled. It must read 101.
5. **Quit with the panel open.** The panel's `close` handler hides unless `quitting` is set. A
   handler that always hides would hang Quit (#31). Pinned: gate 2 item 3 (Quit from the
   panel) and item 8 (Quit from the right-click menu with the panel open).

```js
// Tray popover (#38): the #37 pick (popover-1-menu) as a frameless vibrancy
// panel under the tray icon. Created hidden at launch so a click opens it at
// once; hidden, never destroyed, on dismiss.
const POPOVER_SIZE = { width: 320, height: 197 }; // #37 pick, measured at the empty state
const POPOVER_GAP = 5; // px under the icon, as on the #37 stage (24 px menu bar, panel at 29)
let popoverWin = null;

function createPopover() {
  popoverWin = new BrowserWindow({
    ...POPOVER_SIZE,
    // Non-activating NSPanel: opens on the current Space and over full-screen
    // apps, like a native menu.
    type: 'panel',
    frame: false,
    vibrancy: 'menu',
    visualEffectState: 'active', // keep the blur while the app is inactive, like a menu
    resizable: false, movable: false, minimizable: false, maximizable: false,
    fullscreenable: false,
    skipTaskbar: true,
    acceptFirstMouse: true, // the first click picks a row instead of focusing (#9)
    show: false,
    webPreferences: { contextIsolation: true, sandbox: true,
                      preload: path.join(__dirname, 'preload-popover.js') },
  });
  popoverWin.on('blur', () => popoverWin.hide());
  // Close hides; a real quit (#31's flag) still closes it.
  popoverWin.on('close', (e) => {
    if (quitting) return;
    e.preventDefault();
    popoverWin.hide();
  });
  if (process.env.OPEN_POPOVER === '1')
    popoverWin.once('ready-to-show', () => togglePopover(tray.getBounds()));
  popoverWin.loadFile('popover.html');
}

function togglePopover(trayBounds) {
  if (popoverWin.isVisible()) return popoverWin.hide();
  const display = screen.getDisplayMatching(trayBounds);
  const { workArea } = display;
  // Left edge under the icon's left edge (NSMenu-style), pulled left if the
  // panel would run off the display.
  const x = Math.round(Math.min(trayBounds.x, workArea.x + workArea.width - POPOVER_SIZE.width));
  const y = Math.round(trayBounds.y + trayBounds.height + POPOVER_GAP);
  popoverWin.setPosition(x, y);
  // #22 habit: a panel in the wrong place can be explained from the log.
  console.log(`${new Date().toISOString()} popover: tray=${trayBounds.x},${trayBounds.y} ` +
    `${trayBounds.width}x${trayBounds.height} at=${x},${y} display=${describeDisplay(display)}`);
  popoverWin.show();
  // Below the overlays' 'screen-saver': a flight always renders above the
  // popover. After show, which can re-stack (#12).
  popoverWin.setAlwaysOnTop(true, 'pop-up-menu');
}

// Popover rows act like menu items: the panel closes, then the action runs.
ipcMain.on('popover-test-flight', () => { popoverWin.hide(); testFlight(); });
ipcMain.on('popover-open-settings', () => { popoverWin.hide(); openSettings(); });
ipcMain.on('popover-quit', () => app.quit());
```
