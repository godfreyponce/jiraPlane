# Windows update notice in the tray panel (#67) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> One task, so the change stays uncommitted in the working tree until the owner accepts (AGENTS.md).
> One owner stop: Step 6 (the owner reads the panel on the VM).

**Goal:** On Windows the update check finds Git, and a newer tag shows as `vX.Y.Z available. See
ONBOARDING § 7.` with no Update button; the install path never runs on Windows. The Mac does not change.

**Architecture:** `updater.js` finds `git.exe` on a Windows PATH. `main.js` maps "behind" to a new
phase `manual` on Windows, and skips `blocker()`. `runUpdate()` already runs only for phase
`available`, so neither the panel nor `UPDATE_NOW=1` can start an install on Windows. `popover.html`
renders `manual` in the existing footer line with the existing `available` color and no button.

**Tech Stack:** Electron main process (Node `child_process`, `path`), plain HTML/JS popover.

**Spec:** issue #67 and its parent #60 (Decisions: "Updates are manual at first"; "Look. Same design,
no 3-variant round"). No spec file in `docs/superpowers/specs/`.

## Data flow

```text
main.js checkForUpdate()  (changed: win32 maps "behind" to phase manual)
   |
   v
updater.js resolveBin()  (changed: split PATH on path.delimiter; look for git.exe on win32)
   |
   v
git ls-remote / fetch / rev-parse / merge-base  -->  origin vX.Y.Z tags
   |                                                 (win32: now runs; before, "git not found")
   v
{ tag, relation }
   |
   +-- macOS (unchanged): behind --> updater.blocker() (git status) --> available | blocked
   |                               --> Update button / UPDATE_NOW=1 --> runUpdate()
   |                               --> updater.install() (git checkout, npm install, node install.js)
   |                               --> restartApp()
   |
   +-- win32 (new): behind --> phase manual --> no blocker(), no button, runUpdate() returns early
   |
   v
popover-state IPC --> popover.html #update line  (changed: "vX.Y.Z available. See ONBOARDING § 7.")
```

## Decisions to check at gate 1

1. **The pointer is `See ONBOARDING § 7.`** It matches the `blocked` and `failed` lines, and § 7 is
   ONBOARDING's update section today. #68 writes the Windows steps, so this plan comments on #68
   that the panel points to § 7 (Step 9). If the owner wants the Windows steps in their own section,
   the text and that comment change.
2. **No variant round.** The new line uses the existing footer row and the existing `available` tone.
   It is one new string, and #60's Look decision says no 3-variant round for the port. The owner can
   ask for variants instead.
3. **One gate, not two.** The install is blocked because Windows never reaches phase `available`, and
   `runUpdate()` already returns for any other phase. No extra `win32` check goes in `runUpdate()`.
   Done when 3 is proven on the VM with `UPDATE_NOW=1` (Step 5).
4. **Only Git is fixed for Windows.** `NPM_BIN` stays as it is: on the VM it resolves to the
   extensionless `C:\Program Files\nodejs\npm` shell script, which Windows cannot run, but nothing on
   Windows calls it. The `childEnv` PATH join also moves to `path.delimiter`, because it is the same
   `:` bug and the git children inherit that PATH.

## Global Constraints

- "No Mac behavior change." On macOS `path.delimiter` is `:` and the binary name stays `git`, so
  `resolveBin` is byte-for-byte the same lookup there.
- "Whether one-click update can work on Windows is out of scope here."
- "The manual steps themselves are written in #68. This ticket only points to them."
- Platform checks stay inline as `process.platform === 'win32'`, the style `main.js` already uses.
  No new constant.
- Subagents never launch the app. One running app instance at a time. Stop what you started.
- VM runs pass `TEAMS_WEBHOOK_URL=`. No real secret goes on the VM.
- Commands you hand the owner go in a `bash` fence, one line each (global CLAUDE.md §9).
- Commit format (AGENTS.md `# Commit format`), for the owner's accept: "`summary (refs #N)` — no type
  prefix; never `fixes #N`. Trailers: the harness default `Co-Authored-By` line, nothing else."

## What was checked at planning (VM, read-only)

- `where git` prints `C:\Program Files\Git\cmd\git.exe`. `where npm` prints `...\nodejs\npm` and
  `...\nodejs\npm.cmd`.
- `process.env.PATH.split(':')` on the VM gives `["C", "\\Program Files\\Parallels\\...;C", ...]`, and
  `path.delimiter` is `;`. So today `GIT_BIN` is `''` and the panel says `Couldn't check for updates`.
- `git rev-parse HEAD HEAD` through `execFileSync` returns LF line ends only, so `check()`'s
  `split('\n')` compare works unchanged.
- `git ls-remote --tags --refs origin` works from the VM with no sign-in. The newest tag is `v0.1.5`,
  the one before it `v0.1.4`.
- The VM clone is on `main` at `v0.1.5-6-gab385dd`, with synced edits from earlier tickets.

## Review Focus

1. **A Windows PATH entry with a trailing `\` or quotes** (for example `"C:\Program Files\Git\cmd"`).
   `path.join` handles the trailing slash; a quoted entry is not found. Expect: Git for Windows writes
   no quotes, and the VM check in Step 4 proves the real PATH.
2. **The `manual` line is cut off with `…`** on a narrow font. Expect the whole sentence to show.
   Step 3 measures it in the browser and Step 6 has the owner read it on the VM.
3. **A check failure after `manual` is shown.** Expect `manual` to stay, like `available` does today:
   `manual` is not in the catch block's give-way list, and it must not be added there.
4. **A tray click or `UPDATE_NOW=1` while in `manual`.** Expect no `update: git ... checkout` line in
   the log and HEAD unchanged. Step 5.
5. **The Mac Update button.** Expect it unchanged: the `update` preset still shows the button (Step 3),
   and the Mac launch logs the same check line form as before (Step 8).

- [ ] **Step 1: `updater.js`**

In `resolveBin`, split `process.env.PATH` on `path.delimiter`, not `':'`. Resolve
`GIT_BIN = resolveBin(process.platform === 'win32' ? 'git.exe' : 'git')`. Leave `NPM_BIN` as it is.
In `childEnv`, join the npm dir onto PATH with `path.delimiter`. Update the `launchd` comment above
`resolveBin` only if it now reads wrong; the `#24` reason still holds for the Mac.

- [ ] **Step 2: `main.js` `checkForUpdate()`**

When `relation === 'behind'` on `win32`, do not call `updater.blocker()`, and set phase `'manual'`.
Order of the phase choice: `on` → `current`, `ahead` → `ahead`, then `win32` → `manual`, then
`blocked` / `available` as today. Log line for `manual`, in the existing form:
`<iso> update: check: v0.1.5 available, manual update (Windows)`. Do not touch `runUpdate()`, its
`phase !== 'available'` guard is the gate (Decision 3), and do not add `manual` to the catch block's
give-way list. Add `manual` to the update comment block above `UPDATE_CHECK_MS` in one short line.

- [ ] **Step 3: `popover.html`**

`updateLine`: `case 'manual': return [`${update.tag} available. See ONBOARDING § 7.`, ''];`.
`updateTone`: `manual` gives `'available'`. `buildUpdate` stays as is, so no button. Add a preset
button `<button data-preset="manual">Manual (Windows)</button>` after `Update`, and a `PRESETS`
entry `manual: { ...LIVE, update: { ...NEWER, phase: 'manual', detail: '' } }`.
