# Test flight marks its Teams DM as a test — Implementation Plan

> **For agentic workers:** build this with `/build-ticket 23`. Steps use checkbox (`- [ ]`) syntax
> for tracking. **This project has no test suite (owner rule 2026-08-03) — verify = run the app.**
> Every "verify" step below is something you actually run and actually look at; report what you
> saw at gate 2, never a bare "it works".

**Goal:** Keep the tray's "Test flight" firing both sinks — plane *and* real Teams DM — but make
the DM visibly a test, so a fake `PROJ-142` in a real Teams history can't be mistaken for real
Jira activity.

**Architecture:** The event object is already the only thing that crosses from `dispatchEvent`
into the Teams sink, so it carries the flag: `testFlight()` adds `test: true`, and `teams.js`
decorates the outgoing payload when it sees it. Real poller events never carry the field, so the
#7 fork is untouched by construction — no branch in `dispatchEvent`, no new config, no new file.
The Power Automate flow's six-field layout is fixed and out of scope, so the marker rides
*inside* fields the flow already renders; a seventh field would be silently dropped.

**Tech Stack:** Electron main process, plain CommonJS. No new dependencies.

## Global Constraints

Copied from issue #23 and the owner decision comment:

- **Don't change `dispatchEvent`'s behavior for real events** — that fork is the #7 contract.
- **No new dependency, no new settings file.** `settings.json` is for user prefs, not test rigging.
- **Owner decision (2026-08-06, issue comment):** keep both sinks; mark the test event as a test.
  Splitting the tray and plane-only-test-flight were both considered and rejected.
- **The marker must land in an already-rendered field** (`ticket`, `summary`, `headline`,
  `subline`, `snippet`). The flow's layout does not change as part of this ticket.
- **No double quotes or backslashes in any literal you add to the payload.** `sanitize()` runs
  inside `payload()` — before the marker is applied — so your text is *not* sanitized. The flow
  drops these values into JSON string literals; a stray `"` breaks the card.
- Repo is public. Nothing in a commit, comment, or doc quotes a real ticket key, URL, or secret.

### Task 1: Mark the test event's DM

**Files:**
- Modify: `teams.js:98-101` (`sendForEvent`) and a new `markAsTest` above it
- Modify: `main.js:244-250` (`testFlight`)
- Modify: `AGENTS.md:68-71` (verification recipe — step 5)

**Interfaces:**
- Consumes: `payloadForEvent(ev)` → the flat six-field object
  `{ ticket, summary, headline, subline, snippet, url }` (all strings), or `null` for an unknown
  event type. `dispatchEvent(event)` in `main.js:217` — unchanged by this task.
- Produces: `markAsTest(body)` — mutates the payload in place, returns nothing. Reads nothing
  from the event. The event field is `test: true` (boolean, absent on every real event).

- [ ] **Step 1: Add `markAsTest` to `teams.js`**

Insert directly above `async function sendForEvent(ev)` (currently line 98):

```js
// A test event still reaches this sink by design (#23): the tray's "Test flight"
// and TEST_FLIGHT=1 both go through dispatchEvent, so the one-poller-two-outputs
// fork (#7) stays smoke-testable in one click. The DM therefore has to say so.
// The flow's six-field layout is fixed, so the marker rides inside fields the
// flow already renders — a seventh field would be silently dropped. Nothing here
// is sanitized (payload() ran first), so keep these literals free of quotes and
// backslashes.
function markAsTest(body) {
  body.ticket = `[TEST] ${body.ticket}`;
  body.subline = body.subline
    ? `${body.subline} Sent by a jiraPlane test flight — not a real Jira event.`
    : 'Sent by a jiraPlane test flight — not a real Jira event.';
}
```

Note the `subline` branch: `assigned` (what Test flight sends) leaves `subline` empty, but
`reassigned` and `digest` fill it. Appending rather than overwriting keeps `markAsTest` correct
for any event type someone routes through it later.

```js
// Test flight drives the same dispatchEvent fork a real poll does, so it fires
// BOTH sinks: the plane flies and a real Teams DM goes out. That is deliberate
// (#23, owner decision 2026-08-06) — the two-output design should be
// smoke-testable in one click — and `test: true` makes teams.js mark the DM
// [TEST] so a fake PROJ-142 can't be misread as real Jira activity. Real poller
// events never carry the field, so their DMs are untouched.
// To iterate on overlay visuals without writing to Teams, suppress the sink for
// that run: `TEAMS_WEBHOOK_URL= TEST_FLIGHT=1 npm start` (a shell var beats .env,
// poller.js:33, and an empty webhook URL makes sendForEvent a no-op).
function testFlight() {
  dispatchEvent({
    type: 'assigned',
    issueKey: 'PROJ-142',
    snippet: 'Fix login redirect',
    test: true,
  });
}
```

## Known risk

`markAsTest` prefixes `body.ticket`, matching the option preview the owner picked. If the Power
Automate flow does anything *structural* with `ticket` — a lookup, a link, a regex — rather than
just printing it, the prefix breaks it and Run A will show it. The fallback is to prefix
`body.headline` instead (a pure display string: `[TEST] Tag, you're it — PROJ-142.`) and leave
`ticket` alone. Same one-line shape; decide it from what Run A actually renders.
