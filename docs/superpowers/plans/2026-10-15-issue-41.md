# Popover contract: native menu deleted — Implementation Plan (jiraPlane #41)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement
> this plan. Steps use checkbox (`- [ ]`) syntax for tracking. **Single-task plan:** the code
> stays uncommitted in the working tree until the owner accepts (AGENTS.md "One ticket = two
> sessions"). No ticket branch. **Task 1 Step 8 is gate 2.** Stop there.

**Goal:** The tray has one surface: left click and right click both toggle the popover, and the
native fallback menu (`buildMenu`, its Replay / Banner style / Fly on / Pause polling items, the
`Menu` import) is deleted from `main.js`.

**Architecture:** The right-click handler stops building a native menu and calls the same
`togglePopover(bounds)` the left-click handler calls. Every item the menu carried already has a
home: Test flight, Settings…, Quit and the replay rows are popover rows (#38, #40); Pause is the
popover header switch and the settings window (#39, #29); Banner style and Fly on are settings
window controls (#29). Nothing is added; `buildMenu`, the `Menu` import and the Replay item's
`index = 0` default go. `saveSettings` stays the single writer and is not touched.

**Tech Stack:** Electron 43.2.0, vanilla JS. No new dependency.

**Spec:** No design spec. The decision record is:
- issue #41's body and its one owner comment (`gh issue view 41 --comments`): Done-when 1
  (Settings… opens the #29 window, second click refocuses) shipped in #38; what is left is the
  contract half. Its blockers #38 and #29 are both closed.
- issue #36's body (owner decisions, 2026-09-24): the popover supersedes the slim menu; the
  settings window stays as the deeper surface.
- `docs/HISTORY.md`, the #38 section (line 91: "Right click keeps the native menu until #41")
  and the #39 section (Pause stays session-only).

## Decisions the owner may want to overturn

Most likely to be wrong first.

1. **Right click is the same toggle as left click, not a second behavior.** Both call
   `togglePopover(bounds)`: a right click on a closed panel opens it, a right click on an open
   panel closes it. The ticket says "right click opens the popover"; a right click while it is
   open could instead leave it open. Toggle matches the left click and is one line; strike this
   and the right-click handler becomes `if (!popoverWin.isVisible()) togglePopover(bounds)`.
2. **"Survive restart per #29" is read as: Banner style and Fly on persist; Pause does not.**
   #39 made Pause session-only on purpose and `docs/HISTORY.md` records it. Done-when 3 says all
   three "survive restart per #29", but #29's own persistence rule is the two `settings.json`
   prefs. If Pause should persist, say so: it is a separate ticket (it changes what
   `saveSettings` writes, which this ticket's constraint forbids).
3. **`replayFlight(index = 0)` loses its default.** The native Replay item was the only caller
   that passed nothing. The only caller left is the `'popover-replay'` handler, which always
   passes a row index. The signature becomes `replayFlight(index)`; the comment names the
   popover row as the one caller.
4. **The `docs/usage.md` "Right click opens the menu" list is folded into the panel paragraph,
   not kept as a second list.** Test flight, Settings… and Quit keep their one-line
   descriptions as panel rows; Banner style and Fly on are named as settings-window controls.
   This also closes the "usage.md right-click list lacks Replay and Fly on" minor from #38.
5. **The agent proves the right click with a synthetic CoreGraphics click if the shell has
   Accessibility permission, and otherwise hands it to gate 2.** `CGEventPost` from osascript
   needs the calling terminal in System Settings › Privacy › Accessibility. Step 7 tries once;
   a right click that does nothing in the log is reported as "not provable here", not as a
   failure, and the owner's own right click at gate 2 is the proof.
6. **No design variants.** The ticket adds no visual: the panel that opens on right click is
   the #37 pick, unchanged.
7. **No `ready-for-agent` label.** The owner typing `/run-ticket 41` was the confirmation.

## Native unknowns (find out by running, then apply the named fix)

- **U1: `right-click` does not deliver `bounds` on this Electron.** Electron's docs give the
  `right-click` event `(event, bounds)` on macOS. Seen as: the `popover:` log line after a
  right click reads `tray=undefined,undefined` or the handler throws. Fix: read the bounds from
  the tray instead, `tray.on('right-click', () => togglePopover(tray.getBounds()))`, the same
  call the `OPEN_POPOVER=1` hook already makes.
- **U2: the synthetic right click (Step 7) is swallowed for want of Accessibility permission.**
  Seen as: no new `popover:` line within 2 s of posting the events. Fix: none in this ticket;
  report it and gate 2 item 2 covers it.

```bash
// Usage: osascript -l JavaScript windows.js <pid> — on-screen windows of one process.
ObjC.import('CoreGraphics');
function run(argv) {
  const pid = Number(argv[0]);
  const all = ObjC.deepUnwrap(ObjC.castRefToObject(
    $.CGWindowListCopyWindowInfo($.kCGWindowListOptionOnScreenOnly, 0)));
  return all.filter((w) => w.kCGWindowOwnerPID === pid)
    .map((w) => `id=${w.kCGWindowNumber} layer=${w.kCGWindowLayer} ` +
      `x=${w.kCGWindowBounds.X} y=${w.kCGWindowBounds.Y} w=${w.kCGWindowBounds.Width} h=${w.kCGWindowBounds.Height}`)
    .join('\n') || '(no on-screen windows)';
}
EOF
```

Write the synthetic right-click helper (decision 5, U2):

```bash
mkdir -p /tmp/jp41 && cat > /tmp/jp41/rightclick.js <<'EOF'
// Usage: osascript -l JavaScript rightclick.js <x> <y> — posts a right click at a screen point.
// Needs the calling terminal in System Settings > Privacy & Security > Accessibility.
ObjC.import('CoreGraphics');
function run(argv) {
  const p = $.CGPointMake(Number(argv[0]), Number(argv[1]));
  const down = $.CGEventCreateMouseEvent(null, $.kCGEventRightMouseDown, p, $.kCGMouseButtonRight);
  const up = $.CGEventCreateMouseEvent(null, $.kCGEventRightMouseUp, p, $.kCGMouseButtonRight);
  $.CGEventPost($.kCGHIDEventTap, down);
  $.CGEventPost($.kCGHIDEventTap, up);
  return 'posted';
}
EOF
```
