# Clickable Ticket Link on the Towed Banner (#9) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement
> this plan. Steps use checkbox (`- [ ]`) syntax for tracking. Single-task plan: per
> AGENTS.md, the work stays **uncommitted in the working tree** for gate 2 — no branch,
> no commits until owner acceptance.

**Goal:** Clicking the towed cargo tag during a flight opens the ticket in the browser; everywhere else on screen stays click-through the whole time.

**Architecture:** The overlay windows switch to `setIgnoreMouseEvents(true, { forward: true })` so the page receives mousemove while staying click-through. The renderer runs a per-frame hit-test in the existing pendulum sim loop (NOT mouseenter/mouseleave — see "Why not enter/leave" below) and IPCs the main process to un-ignore mouse events only while the cursor is inside a padded hitbox around the tag. A click while "hot" IPCs main, which `shell.openExternal`s the browse URL it derived for the active flight. A new ~6-line `preload.js` bridges the two IPC calls.

**Tech Stack:** Electron IPC (`contextBridge`/`ipcRenderer` in a sandboxed preload, `ipcMain`/`shell` in main). No new dependencies.

## Owner decision — answered at this gate

The ticket left open: **(a) generous invisible hitbox** vs **(b) hover slows the plane**.

**This plan implements (a)** — a `HIT_PAD` padding around the tag's real bounding box
(starting at 24px, a guess to tune at gate 2 by feel).

Why not (b): the flight is CSS-keyframe driven and multi-display sync (#6) rests on every
window sharing one wall-clock start and one fixed duration; main's teardown timer and the
skywriter timing math assume the same constant. Slowing the plane on hover means a live
playback-rate broadcast to every window plus a dynamic teardown — a rework of the sync
model, not an add-on. If the chase proves annoying at gate 2, widen `HIT_PAD` first; if
that's not enough, (b) becomes its own ticket. **If the owner picks (b) at this review,
this plan needs a rewrite — don't build it as-is and bolt (b) on.**

Also decided (ticket allowed either): **digest flights get no link** (`issueKey` is empty,
there's no single ticket; linking to a dashboard is speculative). Skywriter flights have no
tag, so nothing is clickable there either. Both fall out of the same guard: no URL or no
cargo tag → the feature is inert and the window behaves exactly as today.

## Why not mouseenter/mouseleave (the trap this plan avoids)

Browsers recompute hover **only on actual mouse movement**. The tag moves at ~175px/s, so
it routinely slides out from under a *stationary* cursor — no mousemove fires, so
`mouseleave` never fires, and the naive version of the ticket's pattern leaves the window
capturing clicks (an invisible click-blocking overlay) until the cursor moves again.
Instead: a window-level mousemove listener records the last cursor position, and the
existing per-frame sim loop compares it against the tag's current rect every frame. The
tag flying away from a still cursor disarms on the next frame.

Known accepted limitation: until the first mousemove after page load, the cursor position
is unknown, so a tag flying into a never-moved cursor won't arm. Anyone intending to click
is moving the mouse; not worth extra plumbing.

ipcMain.on('tag-hot', (e, hot) => {

in the tag/puffs from ever being a hover target.

- [ ] **Step 4: plane.html JS — per-frame hit-test state machine**

4a. Insert this block right before `function frame(now)` (~line 416):

```js
    /* ===== clickable tag (#9) =====
       Browsers recompute hover only on real mouse movement, so a tag sliding
       out from under a stationary cursor never fires mouseleave. The hot/cold
       state is therefore driven by a per-frame hit-test in the sim loop:
       last-known cursor (window mousemove — forwarded while click-through,
       real while armed) vs. the tag's current rect + HIT_PAD. */
    const ticketUrl = params.get('url') || '';
    const clickable = !!ticketUrl && bannerStyle === 'cargo' && !!window.jiraPlane;
    const HIT_PAD = 24; // generous hitbox, owner option (a) — a guess; tune by feel
    let cursor = null, hot = false;
    if (clickable) {
      addEventListener('mousemove', (e) => { cursor = { x: e.clientX, y: e.clientY }; });
      addEventListener('click', () => { if (hot) window.jiraPlane.openTicket(); });
    }
    function updateHot() {
      if (!clickable) return;
      const r = tagEl.getBoundingClientRect();
      const inside = !!cursor && document.body.classList.contains('fly') &&
        cursor.x > r.left - HIT_PAD && cursor.x < r.right + HIT_PAD &&
        cursor.y > r.top - HIT_PAD && cursor.y < r.bottom + HIT_PAD;
      if (inside !== hot) {
        hot = inside;
        window.jiraPlane.setTagHot(hot);
        document.documentElement.style.cursor = hot ? 'pointer' : '';
      }
    }
```

4b. Inside `frame()`, call it just before the rAF re-queue:

```js
      updateHot();
      requestAnimationFrame(frame);
```

(The skywriter `repin` loop does NOT call `updateHot` — `clickable` is false there anyway.)

Notes for the implementer:
- `clickable` guards everything: standalone browser previews (`window.jiraPlane`
  undefined), skywriter, digest, and missing-`.env` test flights are all inert — the
  window is never armed and behaves exactly as before this ticket.
- `getBoundingClientRect()` on `#tag` reflects the per-frame transform (translate +
  rotate), so the hitbox follows the swinging tag, twist and all.
- Because the window is armed only while the cursor is inside the padded rect, any click
  that lands while armed is by construction a tag click — hence the window-level click
  listener needs no target check.

## Risks (verify steps cover them)

- `acceptFirstMouse: true` on a `focusable: false` overlay is the documented macOS knob
  for "first click reaches the page", but this exact combination is untested here — step 2
  is the proof. If the first click activates-but-drops, the fallback is arming with
  `win.focusable`-independent `setIgnoreMouseEvents` plus a second click; investigate only
  if step 2 fails.
- Removing the page-level `pointer-events: none` belt: OS-level click-through is still
  fully governed by `setIgnoreMouseEvents`, and step 3's pass-through check plus step 4's
  disarm check are the regression proof. If anything leaks, the belt can return on
  everything except `<html>`.
