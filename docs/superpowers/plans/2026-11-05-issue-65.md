# Settings window can be closed on Windows and uses Windows fonts (#65) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this
> plan. Steps use checkbox (`- [ ]`) syntax for tracking. **One task, so the work stays uncommitted
> in the working tree of `issue-65`.** Two stops: Final Step 3 (owner flies the VM) and Final Step 4
> (gate 2). Run every launch and stop yourself. Do not hand one to a sub-subagent.

**Goal:** On Windows the settings window can be moved, closed, and reopened, and it reads in Windows
fonts, with the same design and no Mac change.

**Architecture:** On Windows only, the window swaps `titleBarStyle: 'hiddenInset'` for `'hidden'`
plus a `titleBarOverlay`, which draws native minimize and close buttons over the page's top right
corner. The page's existing drag regions and the existing close handler do the rest. Every font
stack in `settings.html` gets `'Segoe UI'` after the Mac fonts, so the Mac never reaches it.

**Tech Stack:** Electron 43.2.0 (`titleBarOverlay`, Window Controls Overlay), the VM commands in
`docs/windows-vm.md`.

**Spec:** GitHub issue #65 (`gh issue view 65`). Decisions and fog: parent #60. No design spec.

## Decisions to check at gate 1

1. **Window Controls Overlay, not a native title bar.** The overlay keeps the Mac's look: no title
   bar, the page runs to the window's top edge, and the buttons sit in the empty right end of the
   48 px pane header. It takes one option and no new CSS. The alternative is `frame: true` on
   Windows, with a real title bar. That is the most standard Windows look, but it adds a bar above
   the page, needs `removeMenu()` because a framed window shows a File and Edit menu, leaves the
   sidebar's empty 52 px Mac spacer under a second header, and can draw a white bar over a dark page
   on a light Windows.
2. **The reopen check uses a throwaway hook on the VM, not the tray panel.** The panel's Settings
   row is the real way to reopen the window, but until #64 lands the panel opens off-screen below a
   bottom taskbar. So the build sends the VM a scratch `main.js` that reopens the window 5 seconds
   after a close or a minimize. The hook never enters the worktree or a commit. This proves that
   `openSettings()` shows a hidden window with current values. It does not prove the panel row:
   `popover-open-settings` on Windows is #64's "its rows work" box. The alternative is to wait for
   #64 and click the real row. That is a truer check, but it adds an order between two tickets the
   owner is running side by side. The 5 seconds is a guess: long enough to see the window gone.
3. **The preview's cargo tag keeps its font stack.** `'Marker Felt','Bradley Hand','Comic Sans MS'`
   already reaches a Windows font: on the VM, `comic.ttf` is present and Marker Felt and Bradley Hand
   are not, so Windows shows Comic Sans. #63 owns the real tag in `plane.html`. If #63 is on `main`
   when you build and it picked a different Windows font for the tag, report the mismatch at gate 2.
   Do not change `plane.html`.

## What was checked at planning

Read from Electron's source at tag `v43.2.0`, and not run:

- **`hiddenInset` on Windows has no window controls.** Any non-normal style makes the window
  frameless (`native_window.cc:80-81`). Controls come only from the overlay, and on Windows the
  overlay turns on only with `TitleBarStyle::kHidden`: the `kHiddenInset` branch is inside
  `#if BUILDFLAG(IS_MAC)` (`native_window.h:391-399`). So adding `titleBarOverlay` alone does nothing:
  the style must change too.
- **Only minimize and close show.** A non-maximizable window hides the maximize button
  (`win_caption_button_container.cc:155-158`).
- **The buttons take clicks above a drag region.** The hit test checks the button container first
  (`win_frame_view.cc:83-94`).
- **`height` can stay at its default.** The docs say it defaults to the system height. The pane
  header is 48 px and the preview starts below it, so the buttons cover nothing as long as the
  default stays under 48. Step 4 looks at this.

Read over SSH from the VM, with the app not running:

- `segoeui.ttf`, `segoeuib.ttf`, `seguisb.ttf`, `seguibl.ttf`, and `comic.ttf` are present.
  `ARLRDBD.TTF` (Arial Rounded) and `BRADHITC.TTF` are not. Office adds them, so the coworker's PC
  may differ. On the VM the skywriter preview letters use Segoe UI's heavy weight.
- No `settings.json`, no `.env`, and no `electron.exe` running.

Read from `settings.html`:

- By adding up the CSS, General is the tallest pane, at about 426 of 460 px. Its rows inherit the
  fixed `line-height: 1.3`, so a new font does not make them taller. Clipping is unlikely. Final
  Step 3 is what proves it.

## Review Focus

1. **Windows display scale at 125% or 150%.** This is common on laptops, and the coworker's setting
   is unknown. The panes must still fit, with no clipped text. Final Step 3 sets 150% once.
2. **Minimize, then reopen.** A minimized window must come back when Settings is opened again. From
   memory of Chromium's code, `show()` restores it, but neither that nor the source was checked. Final
   Step 3 tests it and holds the fallback.
3. **Alt+F4 and the taskbar's Close window.** Both must hide the window like the close button and
   leave the app running. Final Step 3 tests Alt+F4 and the `electron` count.
4. **The window opening behind a maximized app.** `app.focus({ steal: true })` is a Mac option, and
   on Windows the window must still come to the front. Final Step 3 opens it over Notepad.
5. **One VM, four tickets.** #63, #64, and #66 have worktrees at the same commit, and the VM has one
   clone and one app. The start script ends any running copy, and a sync overwrites the clone. Step 1
   checks first. If `electron.exe` is running on the VM, another session may be using it: stop and
   ask the owner. Do not kill it.
