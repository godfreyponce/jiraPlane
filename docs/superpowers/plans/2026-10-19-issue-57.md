# Popover always shows update status — Implementation Plan (jiraPlane #57)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement
> this plan. Steps use checkbox (`- [ ]`) syntax for tracking. **Single-task plan:** the change
> stays uncommitted in the working tree of this worktree (branch `issue-57`). Never commit,
> never merge to main. One stop: Step 8 is gate 2.

**Goal:** The #48 header line in the popover is always there. It says checking, up to date
(with the version), ahead of the newest tag, a newer tag is available, can't update, or
couldn't check, plus a relative last-checked time where the ticket's table gives one.

**Architecture:** `updater.check()` returns where HEAD stands against the newest remote
`vX.Y.Z` tag (`behind` / `on` / `ahead`) instead of only "a newer tag or null". `main.js`
keeps the `update` popover field always set: it starts at `checking`, a good check stamps
`checkedAt`, and a failed check becomes `check-failed`. `popover.html` renders the new phases
in the same `#update` slot. The element is rebuilt only when the phase, tag, ref, or detail
changes. On every 1 s push the line's text is rewritten in place, so the time moves and the
Update button stays the same DOM node.

**Tech Stack:** Electron ^43.2.0, vanilla HTML/CSS/JS, `child_process.execFile` (git). No new
dependency.

**Spec:** No design spec. The decision record is issue #57's body
(`gh issue view 57 --json body -q .body`, no comments) and its owner decisions Q1–Q4. It builds
on #48 (`docs/superpowers/plans/2026-10-16-issue-48.md`: the contract, the copy table, the
scratch-clone proof).

## Decisions the owner may want to overturn

Most likely to be wrong first.

1. **A failed daily check does not hide a newer tag that is already known.** If the line says
   `available` or `blocked`, a later failed check leaves it as it is (the tag is already
   fetched, so the Update click still works). A failed check replaces only `checking`,
   `current`, `ahead`, and an earlier `check-failed`. The other choice, "a failure always
   replaces the line", would hide the Update button for up to 24 h after one Wi-Fi blip.
2. **`Couldn't check for updates` is muted grey, not red.** Being offline is common and needs
   no action. Red stays for `Can't update` and `Update failed`, which do need action.
3. **"On the newest tag" means HEAD is the tag's commit.** On a branch or detached, it makes no
   difference. The owner's main checkout reads `main · ahead of vX.Y.Z` as soon as it has one
   commit past the tag (the docs commit after a tagged merge does that). At the exact tag
   commit, it reads `vX.Y.Z · Up to date`.
4. **The `ahead` label is the branch name, or the short commit when HEAD is detached.** A
   worktree reads, for example, `issue-57 · ahead of v0.1.2 · …`. Long branch names are cut
   with an ellipsis.
5. **No remote `vX.Y.Z` tags at all counts as a failed check** (the ticket's table puts "no
   remote tags" in the check-failed row). The log line names it.
6. **ONBOARDING § 7 is not changed.** What it says is still true. A sentence about
   `Up to date` / `Couldn't check` can go in the accept-time docs commit if the owner wants it.
7. **No `ready-for-agent` label.** The owner typing `/run-ticket 57` was the confirmation.

## The contract (changes to #48's `update` field)

`update` is never `null` now. Shape:

```js
update: {
  phase: 'checking' | 'current' | 'ahead' | 'check-failed'            // new (#57)
       | 'available' | 'installing' | 'restarting' | 'blocked' | 'failed', // #48, unchanged
  tag: '',          // newest vX.Y.Z on origin; '' until a check succeeds
  ref: '',          // ahead only: branch name, or short commit if detached; else ''
  detail: '',       // blocked: the reason; failed: the last stderr line; else '' (#48)
  checkedAt: null,  // ms of the last successful check; null before one
}
```

Initial value in `main.js`: `{ phase: 'checking', tag: '', ref: '', detail: '', checkedAt: null }`.

Copy for the new phases (exact; `ago()` is popover.html's existing function):

| phase | line | tone |
|---|---|---|
| `checking` | `Checking for updates…` | info |
| `current` | `${tag} · Up to date · checked ${ago(checkedAt)}` | info |
| `ahead` | `${ref} · ahead of ${tag} · checked ${ago(checkedAt)}` | info |
| `check-failed` | `Couldn't check for updates · checked ${ago(checkedAt)}`, or `Couldn't check for updates` when `checkedAt` is null | info |

`info` tone: muted (`var(--muted)`), `grid-column: 1 / -1` (no button, so the line uses the
full header width), one line, ellipsis. The #48 phases keep their copy and tones.

**Interfaces:**
- Produces: `updater.check(repoDir) → Promise<{ tag: string, relation: 'behind'|'on'|'ahead', ref: string }>`.
  It rejects when git is missing, when the remote is not reachable, or when origin has no
  `vX.Y.Z` tag (message `no vX.Y.Z tags on origin`). `ref` is set only for `ahead`.
  `blocker` and `install` do not change.

- [ ] **Step 1: `updater.check` returns the relation**

Keep the existing tag listing, semver pick, and `fetch … tag <tag>`. Then:
- no tags → `throw new Error('no vX.Y.Z tags on origin')`;
- `git rev-parse HEAD <tag>^{commit}`: the two lines are the same → `{ tag, relation: 'on', ref: '' }`;
- `merge-base --is-ancestor <tag> HEAD`: exit 0 → `ahead`, with `ref` = `git symbolic-ref
  --short -q HEAD`. If that exits 1 (detached), `ref` = `git rev-parse --short HEAD`. Exit 1 →
  `{ tag, relation: 'behind', ref: '' }`. Any other error is thrown, as today.
Update the comment above `check` to match.

- [ ] **Step 2: `main.js` keeps `update` always set**

- `let update = { phase: 'checking', tag: '', ref: '', detail: '', checkedAt: null };`, with
  the comment naming #57.
- `checkForUpdate`: keep its guards and the `holdingFlights()` re-check. On success:
  `reason = relation === 'behind' && await updater.blocker(__dirname)`. Phase: `on` →
  `current`, `ahead` → `ahead`, `behind` → `blocked` if there is a reason, else `available`.
  Then `setUpdate({ phase, tag, ref, detail: reason || '', checkedAt: Date.now() })`. Log line:
  `update: check: <tag> current | <ref> ahead of <tag> | <tag> available | <tag> blocked (<reason>)`.
- Catch: keep the log line. Then, unless `holdingFlights()` or the phase is `available` /
  `blocked` (decision 1): `setUpdate({ phase: 'check-failed', tag: '', ref: '', detail: '', checkedAt: update.checkedAt })`.
- `runUpdate`: each `setUpdate({ tag, phase: X, detail: Y })` becomes
  `setUpdate({ ...update, phase: X, detail: Y })`. Nothing else changes.
