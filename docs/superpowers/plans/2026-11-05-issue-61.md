# Windows test VM: open an app on the VM's desktop from the Mac (#61) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this
> plan. Steps use checkbox (`- [ ]`) syntax for tracking. **Single-task plan:** the work stays
> uncommitted in the working tree of this worktree (branch `issue-61`). Never commit, never merge
> to main. Three stops: Step 2 (owner installs), Step 7 (owner reads the VM's window), Step 14
> (gate 2). Run this plan yourself. Do not hand a launch or a stop to a sub-subagent.

**Goal:** From the Mac, one tested command each to read the VM's version and CPU, start Electron on
the VM's desktop with chosen env vars and a readable log, and stop it, all written to
`docs/windows-vm.md`.

**Architecture:** An SSH session on Windows runs in session 0, which has no desktop. A scheduled
task with an interactive logon runs in the signed-in user's desktop session, so
`scripts/windows-vm-start.ps1` (new) registers and starts one task per launch, with the env vars
and the log redirect in the task's command line. The real app crashes on launch on Windows until
#62, so the proof uses a throwaway probe that `npm start` runs through a temporary `main` swap in
the VM's clone. The probe is deleted before gate 2.

**Tech Stack:** Parallels Desktop, Windows 11 on Arm, Windows OpenSSH (in-box), Task Scheduler
PowerShell cmdlets, Electron `^43.2.0`, macOS `ssh`/`scp`/`tar`.

**Spec:** GitHub issue #61 (`gh issue view 61`). Decisions and fog: parent #60. Next user of these
commands: #62 ("using the launch command from #61").

## Decisions to check at gate 1

1. **One tracked script, beyond the ticket's "Probably touches".** `scripts/windows-vm-start.ps1`
   holds the launch so quoting does not pass through zsh, ssh, cmd, and PowerShell on every run. It
   is test-rig tooling, not app code, and the app never loads it. The alternative is a doc-only
   setup block pasted onto the VM. That leaves the running copy free to drift from the doc.
2. **The proof uses a probe, not the app.** `process.getuid()` runs at `main.js:681` at module load,
   so the app dies before it opens anything on Windows. The ticket's words are "starts Electron".
3. **A sync command is added, beyond the Done when list.** The ticket says a build session can
   "pull", but the global hook blocks agents from `git push`, so a ticket branch never reaches
   GitHub before accept. Without a way to send the worktree, #62 stalls on its first launch. The
   sync is one `tar` over `ssh` line in the doc. Drop it and #62's builder must ask the owner to
   push `issue-62` for every iteration.
4. **A dedicated SSH key with no passphrase.** `~/.ssh/windows-vm`, used only for this VM. A build
   session cannot answer a passphrase prompt, and the owner's main key stays off the VM.
5. **Costs the owner meets first.** At planning time Parallels is not installed on this Mac
   (`prlctl` not found, nothing in `/Applications`). Parallels Desktop is paid after its trial, and
   Windows has its own activation (Parallels KB 114051). The plan relies on neither `prlctl` (from
   memory, a Pro edition feature) nor activation. One forward note, from memory and unchecked:
   unactivated Windows may lock the Personalization page, and #62 needs a dark and a light taskbar.

**What is known and what is not.** From Microsoft's docs, read at planning time: the OpenSSH
capability names and service commands, the `OpenSSH-Server-In-TCP` firewall rule, the
`administrators_authorized_keys` location and ACL with SIDs, no key auth for Entra ID accounts, and
the three-day default task time limit. **Not tested by anyone yet:** that session 0 has no desktop
here, that an interactive task reaches the desktop, that Electron's console output survives the
`cmd` redirect, that tasks refuse to start on battery by default, and that a blank value removes a
variable. The steps below prove or disprove each one. Where a command below turns out wrong, change
it and say so in the gate 2 report. The doc records what ran, not what this plan guessed.

## Review Focus

1. **The VM restarted and nobody is signed in.** A task with an interactive logon has no session to
   run in, so a launch can appear to succeed and show nothing. `windows-vm-start.ps1` must exit
   non-zero with a plain message. Step 9.
2. **Start while a run is still going.** Task Scheduler can ignore a second start, and the app's
   single-instance lock can make a second copy exit. Start must replace the old run. Step 8.
3. **The Mac runs on battery.** Parallels may pass the battery state to the guest, and a default task
   may refuse to start. The task's settings must allow it. Step 7.
4. **A blank env value.** `TEAMS_WEBHOOK_URL=` means "blank, and beats `.env`" on the Mac
   (`poller.js:33`). `cmd`'s `set "X="` removes the variable instead, so at #68, with a real `.env`
   on the VM, a "silent" run would read the webhook from `.env` and send a real DM. Measure it and
   write the result in the doc. Step 8.
5. **Node installed as x64 on the Arm VM.** Emulated Node would fetch an x64 Electron, and the VM
   would then test the wrong binary without saying so. `node -p process.arch` must print `arm64`.
   Step 3.

- [ ] **Step 1: Write the script and the setup half of the doc**

`scripts/windows-vm-start.ps1`, as a candidate. Comment only the why (a task is the way out of
session 0):

```powershell
$ErrorActionPreference = 'Stop'
if (-not (Get-Process explorer -ErrorAction SilentlyContinue)) {
  Write-Output 'Nobody is signed in on the VM desktop. Sign in, then run this again.'
  exit 1
}
Get-Process electron -ErrorAction SilentlyContinue | Stop-Process -Force -PassThru | Wait-Process
$log = "$env:USERPROFILE\jiraplane-vm.log"
Remove-Item $log -ErrorAction SilentlyContinue
$sets = ($args | ForEach-Object { "set `"$_`"&& " }) -join ''
$action = New-ScheduledTaskAction -Execute 'cmd.exe' -WorkingDirectory "$env:USERPROFILE\jiraPlane" `
  -Argument "/c `"$($sets)npm start > `"$log`" 2>&1`""
$principal = New-ScheduledTaskPrincipal -UserId $env:USERNAME -LogonType Interactive
$settings = New-ScheduledTaskSettingsSet -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries -ExecutionTimeLimit 0
Register-ScheduledTask jiraplane-vm -Action $action -Principal $principal -Settings $settings -Force | Out-Null
Start-ScheduledTask jiraplane-vm
```

`Stop-ScheduledTask` joins this if the old task instance outlives Electron. The log is deleted first
so a launch that never ran cannot pass for one that did. A console window on the VM's desktop is
expected. Hiding it is out of scope unless the owner asks at gate 2.

`docs/windows-vm.md`, setup section, in this order. Each step names its window (Mac Terminal, VM
admin PowerShell, VM Command Prompt):

1. **Mac:** `ssh-keygen -t ed25519 -N '' -C windows-vm -f ~/.ssh/windows-vm`, then
   `pbcopy < ~/.ssh/windows-vm.pub`.
2. **Mac:** install Parallels Desktop, click **Install Windows** in the prompt (Parallels KB 125375:
   the wizard downloads the Arm image). Use a local account, because key auth does not work with
   Entra ID accounts. Stay in Window view, not Coherence. Turn off any Parallels option that pauses
   Windows when idle (look up the current menu path when you write this step).
3. **VM admin PowerShell, one paste.** Git and Node first, so `sshd` starts with them on its PATH:
   `winget install --id Git.Git -e --source winget`,
   `winget install --id OpenJS.NodeJS.LTS -e --source winget`,
   `Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0`, `Start-Service sshd`,
   `Set-Service -Name sshd -StartupType Automatic`, Microsoft's firewall-rule check for
   `OpenSSH-Server-In-TCP`, writing the pasted public key to
   `$env:ProgramData\ssh\administrators_authorized_keys`,
   `icacls.exe "$env:ProgramData\ssh\administrators_authorized_keys" /inheritance:r /grant "*S-1-5-32-544:F" /grant "SYSTEM:F"`,
   and `powercfg /change standby-timeout-ac 0` with the `-dc` and `monitor-timeout` forms. If
   `winget` is missing, install from git-scm.com and nodejs.org and pick the Arm64 installers.
4. **VM, new Command Prompt, not admin:** `git clone https://github.com/godfreyponce/jiraPlane.git`,
   `cd jiraPlane`, `npm install`. If `node_modules\electron\dist` is missing afterwards,
   `node node_modules\electron\install.js` (#53).
5. **VM:** `ipconfig` for the IPv4 address and `whoami` for the user name.
6. **Mac, one line:** `printf` appending to `~/.ssh/config` a `Host windows-vm` block with `HostName`,
   `User`, `IdentityFile ~/.ssh/windows-vm`, `IdentitiesOnly yes`, and
   `StrictHostKeyChecking accept-new`. The doc shows `<VM-IP>` and `<VM-USER>` as placeholders.
7. **Coworker:** Settings, System, About, then read **Version** and **System type**. Nothing else
   about the PC is needed.

Add a short "If it fails" list: `Permission denied (publickey)` means a standard account (use
`%USERPROFILE%\.ssh\authorized_keys`) or a bad ACL on the key file; a timeout means the VM is
suspended, off, or has a new IP (`ipconfig`, then edit `~/.ssh/config`).
