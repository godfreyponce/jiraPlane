# Tray icon: paper plane from the popover stage — Implementation Plan (jiraPlane #52)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement
> this plan. Steps use checkbox (`- [ ]`) syntax for tracking. **Single-task plan:** the change
> stays uncommitted in the working tree until the owner accepts (AGENTS.md "One ticket = two
> sessions"). The worktree is already on branch `issue-52`; do not commit. **Task 1 Step 9 is
> gate 2.** Stop there.

**Goal:** The menu-bar icon is the paper plane the popover's preview stage draws, not the
right-pointing arrowhead the app ships today.

**Architecture:** Two PNGs change and one SVG is added. `assets/iconTemplate.svg` holds the
stage's three paths (`popover.html:193-197`) with `fill="#000"` instead of `#fff`, the same
`fill-opacity` values (1, .72, .5), on a `0 0 16 16` viewBox. Homebrew's `rsvg-convert`
(already on the owner's Mac, 2.62.3) renders it to `assets/iconTemplate.png` (16 × 16) and
`assets/iconTemplate@2x.png` (32 × 32). `main.js:697-700` does not change: Electron marks a
file whose name ends in `Template` as a template image and picks up the `@2x` file by name, so
macOS tints the black-plus-alpha plane for light and dark menu bars as it does today.

**Tech Stack:** SVG, `rsvg-convert` 2.62.3 (Homebrew, render-time only, not a project
dependency), ImageMagick 7 (`magick`, Homebrew, used only to read the PNGs back), electron 43.2.0.

**Spec:** No design spec. The decision record is issue #52's body:

- **Done when:** both PNGs draw the stage SVG's paper plane, black on transparent, as template
  images; the running app shows it in light and dark menu bars and still opens the popover on
  left and right click; the three tones still read as one shape at 16 px, else the owner picks
  a flat version.
- **Constraints:** template image (black + alpha only); no new runtime dependency, a one-off
  render script that does not ship is fine; the shape is already picked, so the visual rule's
  three variants apply only if the 16 px render needs a different shape.

## Decisions the owner may want to overturn

1. **The SVG source is committed as `assets/iconTemplate.svg`.** The ticket allows a render
   script that does not ship; committing the 300-byte source instead means the next icon edit
   starts from a file, not from re-reading `popover.html`. It is not loaded at runtime. The
   render command lives in this plan and in the HISTORY entry, not in a script file.
2. **Toned stays; flat is a fallback, not a variant set.** A planning probe (2026-10-16)
   rendered both at 16 and 32 px, tinted black on white and white on `#262626`, and scaled up:
   the toned plane shows the wing fold at 16 px; the flat one merges both wings into a single
   arrowhead with a small keel. So the plan ships the toned PNGs and writes the flat pair to
   `design-directions/icon-52/` (git-ignored) only for the owner's pick if the tones do not
   read on their menu bar. The stage SVG's geometry (bbox 1.2–14.8 × 1.4–14.4 on a 16 grid) is
   kept as-is: no re-centring, no padding change.
3. **Dark mode is toggled by the build and restored.** Done-when names both menu bars. The
   build reads the current `dark mode` value with `osascript`, flips it for one screenshot, and
   sets it back. If the owner would rather the build not touch Appearance, Step 7 shrinks to
   the current appearance only and the owner checks the other.

## Tray icon: paper plane from the popover stage — #52 (2026-10-17) — ACCEPTED & CLOSED; commit <hash>
